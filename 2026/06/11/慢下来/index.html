慢下来

前阵子翻自己的 GitHub 提交记录，密密麻麻一片绿。

看着挺有成就感。但仔细一想，那些绿格子背后，有多少是真正有价值的事？又有多少只是”看起来很忙”？

忙，不等于有意义。

被加速的生活

我们这个行业，节奏快得离谱。

  • 框架半年一更，不学就落伍
  • 新技术层出不穷，FOMO 逼着你追
  • 996 被包装成”奋斗”，摸鱼被污名化为”不上进”

更可怕的是，这种焦虑会渗透到生活的每个角落。看书要”速读”，学习要”碎片化”，连放松都变成了”高效休息法”——好像连歇着都得有方法论。

我们活成了一个永远在加载中的网页。

慢下来之后

最近刻意让自己慢了一些。

不刷技术热点了，把一本买了三年的纸质书翻出来看。不追求”今天学了多少”，而是”今天想明白了什么”。

奇怪的事情发生了：

  • 代码写得更少了，bug 也更少了
  • 不追新技术，反而把老东西理解得更透
  • 少刷手机，多了很多空白时间——用来发呆，用来散步，用来什么都不做

慢，不是懒。慢是一种选择。

慢工出细活

回头看自己写过的那些博客文章，质量最高的往往是花了时间的。慢慢查资料、慢慢想结构、慢慢打磨用词。

而那些为了”保持更新频率”赶出来的，自己都不愿意再看第二遍。

写代码也一样。快速堆出来的功能，后来都要花更多时间填坑。不如一开始就慢一点，想清楚再动手。

省下来的时间，其实都在后面加倍还了。

怎么慢下来

不是什么大道理，就几个小习惯：

  1. 每天留一小时空白 —— 不安排任何事，想干嘛干嘛
  2. 关掉推送 —— 消息是别人的优先级，不是你的
  3. 一件事做完再做下一件 —— 多线程是 CPU 的事，人脑不适合
  4. 接受”不完美” —— 不用每条朋友圈都回，不用每个需求都接

写在最后

这个时代不缺快的人，缺的是敢慢下来的人。

快，让你跑得远。慢，让你知道往哪跑。

偶尔停下来，看看路，也挺好的。

写于一个没有排期的下午。
